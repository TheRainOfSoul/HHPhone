# HHPhone — push через Firebase и звонилка по умолчанию (дизайн)

Дата: 2026-10-13. Статус: утверждён в обсуждении, ждёт ревью спеки.
Связано: `2026-10-08-hhphone-design.md`, `2026-10-12-hhphone-tokens-design.md` (обмен токена `claim.php`, закрепление SPKI).
Версии: HHPhone 0.4.0, HHPBX 1.10.0.

## Цель

HHPhone полностью заменяет стандартную звонилку Samsung/Android: звонки с SIM и звонки через HHPBX в одном приложении.
Входящие на учётки HHPBX доходят, даже когда HHPhone закрыт или выгружен системой, — через push Firebase, без постоянной связи и значка в шторке.

## Решения пользователя

| Вопрос | Решение |
|---|---|
| Роль HHPhone | Полная замена звонилки, вместе со звонками с SIM |
| Поведение в фоне | Только push (как WhatsApp): закрыт — связи со станцией нет, значка нет |
| Где ключ Firebase | На каждой HHPBX (станция шлёт push сама, без посредника) |
| Учётки с чужих АТС | Для них постоянная связь и значок, как сейчас; push только для HHPBX |
| Транк к оператору | Нет; звонки в город через станцию — вне этой работы |
| Тестовый телефон | Samsung Galaxy S24 Ultra пользователя, отладка по Wi-Fi через Tailscale (пара по коду) |

## 1. Входящий звонок

1. Звонок на внутренний номер (например 101) доходит до диалплана `local_extension` (890).
2. Перед ним новый шаг `hhphone_push` (885): если у номера есть push-токены — HHPBX шлёт push каждому токену (в фоне, не задерживая звонок), отвечает звонящему `ring_ready` (180) и ждёт регистрации номера **до 10 секунд**, проверяя `sofia_contact` каждые 0,5 с.
3. Номер уже зарегистрирован (приложение открыто) — push всё равно уходит (контакт может быть устаревшим), но без ожидания.
4. Телефон проснулся и зарегистрировался → `bridge` как обычно (стандартный `local_extension`, ничего в нём не меняем).
5. Не зарегистрировался за 10 с → шаг завершается, `local_extension` идёт по обычным правилам (`continue_on_fail`, голосовая почта, переадресация).
6. Токенов у номера нет — шаг ничего не делает (поведение станции без HHPhone не меняется).

Push — data-сообщение FCM с `android.priority = HIGH`, `ttl = 10s`, содержимое `{"t":"call"}`: ни номера, ни имени, ни домена. Телефон по нему регистрирует все свои push-учётки.

## 2. HHPBX

### Таблица и адрес регистрации токена

`v_hhphone_push`: `hhphone_push_uuid`, `domain_uuid`, `extension_uuid`, `fcm_token` (уникальный), `insert_date`, `update_date`.
Таблица — через `app_config.php` приложения `app/hhphone` (как `v_hhphone_tokens`). Удаление номера → его токены удаляются (запросом в той же операции, где FusionPBX удаляет номер, либо проверкой `enabled` при отправке — что меньше правит upstream; решается в плане).

`POST /app/hhphone/push.php` (form-urlencoded, HTTPS, тот же канал и закрепление SPKI, что у `claim.php`):

| Поле | Значение |
|---|---|
| `user`, `domain`, `pass` | SIP-учётка (номер, домен, пароль) — так станция проверяет, что токен принадлежит номеру |
| `token` | FCM-токен (до 4096 символов, `[A-Za-z0-9_:-]`) |
| `op` | `set` — сохранить/обновить, `del` — удалить |

- 200 `{"ok":true}`. Любая ошибка проверки — 403 `{"error":"denied"}` без подсказок; неверный формат — 400.
- Пароль сравнивается `hash_equals` с `v_extensions.password` включённого номера домена.
- Один номер — несколько токенов (несколько телефонов); один токен — один номер (`set` переносит токен).

### Отправка push

- `app/hhphone/resources/classes/hhphone_fcm.php`: FCM HTTP v1. OAuth2: JWT RS256 (`openssl_sign`) из service account → `https://oauth2.googleapis.com/token`, токен доступа кэшируется в файле рядом с ключом до истечения (−5 мин). Отправка: `POST https://fcm.googleapis.com/v1/projects/<project_id>/messages:send`, таймаут 5 с.
- Ответ `404 UNREGISTERED` / `400 INVALID_ARGUMENT` по токену → токен удаляется из таблицы.
- CLI-обёртка `app/hhphone/push_send.php <domain> <extension>` — отправить всем токенам номера; её запускает Lua через `bg_system` (фоном).
- Lua `app/switch/resources/scripts/app/hhphone_push/index.lua` (вызов `lua app.lua hhphone_push`): проверка наличия токенов одним запросом через `Database` FusionPBX, запуск отправки, ожидание регистрации. Путь к PHP — тот же, что используют другие вызовы PHP со станции (Windows и Debian); уточняется в плане.
- Диалплан `885_hhphone_push.xml` (`app_uuid` новый, `global="true"`, условие `${user_exists} = true`), добавляется в существующие домены через `app_defaults` при обновлении.

### Ключ Firebase

- **Выпуски HHPBX публичны (files.dg-solutions.am), поэтому ключ в установщик и пакеты не кладётся** — иначе его мог бы скачать кто угодно, а не только клиенты.
- Ключ (JSON service account) загружается в панели: «HHPhone» → блок «Push-уведомления» → «Загрузить ключ Firebase». Хранится вне веб-корня: Debian `/etc/hhpbx/fcm.json` (владелец www-data, 0600), Windows — каталог данных HHPBX рядом с настройками, права только у службы.
- Блок показывает: ключ есть/нет, `project_id`, кнопка «Проверить» (получение OAuth-токена) и «Удалить».
- Нет ключа — push не отправляется, звонки идут как раньше; страница HHPhone показывает предупреждение.
- Станции нужен исходящий HTTPS до `oauth2.googleapis.com` и `fcm.googleapis.com`.

## 3. HHPhone

### Firebase

- Зависимость `com.google.firebase:firebase-messaging` (BoM) и плагин `google-services` — только для flavor `hh`.
- `app/src/hh/google-services.json` в репозитории: в нём нет секретов (ключ API Android ограничен приложением), это допустимо для публичного кода. Секретный ключ service account — только на станциях.
- `HHPushService : FirebaseMessagingService`:
  - `onNewToken` → перерегистрировать токен на всех HHPBX-учётках.
  - `onMessageReceived` с `t = call` → запустить `BaresipService` как foreground (тип `phoneCall`; разрешено из high-priority FCM), зарегистрировать push-учётки, держать до звонка или 30 с.

### Вид учётки

- При обмене `claim.php` HHPhone теперь сохраняет для учётки `server` и `spki` из QR (в своих настройках по AoR). Учётка с `server` — **HHPBX-учётка**.
- После добавления — сразу `push.php op=set`. Ошибка (нет сети, станция старше 1.10.0 — 404) → учётка работает как «чужая» (постоянная связь), повтор при следующем запуске.
- Удаление учётки → `push.php op=del` (без ожидания результата).
- Учётки, добавленные до 0.4.0, и учётки чужих АТС — «чужие». Перевести старую HHPBX-учётку на push — заново отсканировать QR из панели.

### Жизненный цикл BaresipService

`HHPushPolicy` (чистая функция, покрывается тестами) решает, держать ли связь:
- есть хоть одна «чужая» включённая учётка → всегда (как сейчас, значок в шторке);
- иначе — пока экран приложения открыт, идёт звонок, или прошло < 60 с после закрытия/звонка/push;
- после этого — снять регистрации (`unregister`, чтобы станция не звонила на мёртвый контакт) и остановить сервис.

Исходящий из закрытого приложения (`tel:` из контактов, кнопка звонилки) открывает приложение → сервис стартует, регистрирует и звонит.

Ограничение: SIP-сообщения (чат) на HHPBX-учётки при закрытом приложении не приходят до следующего открытия.

### Батарея Samsung

При первой HHPBX-учётке, если HHPhone под оптимизацией батареи, — один раз диалог «Чтобы звонки доходили, разрешите HHPhone работать без ограничений батареи» → системный запрос `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`. Отказ не мешает работе.

## 4. Звонилка по умолчанию и SIM

Основа уже есть в baresip+ (`InCallService`, `ConnectionService`, роль `ROLE_DIALER`) и работает у пользователя: входящий SIM-звонок прошёл через HHPhone. В этой работе — проверка на S24 Ultra и исправление найденного:

- входящий и исходящий по SIM, удержание, второй звонок, гарнитура/Bluetooth;
- **112** (и 101–103) — набираются, уходят через SIM;
- выбор «SIM или станция» при наборе номера;
- экран звонка (SIM и SIP) в цветах HHDesign, обе темы;
- push: телефон спит, приложение смахнуто из недавних, режим энергосбережения Samsung, перезагрузка телефона.

## Ошибки

| Ситуация | Что происходит |
|---|---|
| У станции нет интернета / ключа | Push не уходит, звонок через 10 с (или сразу без токенов) идёт по обычным правилам |
| Телефон выключен или без сети | Ожидание 10 с, дальше обычные правила |
| FCM вернул «токен недействителен» | Токен удаляется со станции |
| `push.php` недоступен | Учётка работает с постоянной связью, повтор при запуске |
| Пользователь отказал в разрешении батареи | Работает; на Samsung push может опаздывать |

## Тестирование

- HHPBX: тесты `windows/tests` и `linux/tests` — проверка `push.php` (верный/неверный пароль, перенос токена, `del`), JWT (подпись тестовым ключом и проверка открытым), удаление токена по `UNREGISTERED` (подменённый HTTP), наличие диалплана 885 после `app_defaults`.
- HHPhone: unit-тесты `HHPushPolicy` (все сочетания: чужая учётка, открыт экран, звонок, таймер) и разбора/сохранения `server`/`spki`.
- Стенд: HHPBX hhpbx-test + эмулятор с Google Play (FCM) + S24 Ultra через Tailscale. Сценарий: закрыть HHPhone → позвонить на номер с другого номера → звонок доходит; выключить сеть телефона → через 10 с голосовая почта.

## Вне работы

Транк к оператору и звонки в город; push для чата; push для чужих АТС; свой push-посредник.
