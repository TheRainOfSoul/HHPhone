# HHPhone — SIP-звонилка для Android (дизайн)

Дата: 2026-10-08. Статус: утверждён в обсуждении, ждёт ревью спеки.

## Цель

Звонилка на Android, работающая через HHPBX и любые другие SIP-АТС.

Кто пользуется:
- **сотрудники клиентов** (отели и офисы на HHPBX) — внутренний номер на личном телефоне, настройка по QR, менять ничего не могут;
- **админ** — несколько учёток на АТС разных клиентов для проверки линий;
- **в будущем Google Play**.

Успех: сотрудник сканирует QR и через минуту звонит и принимает звонки (голос и видео), даже когда приложение свёрнуто; админ держит в одном телефоне учётки нескольких АТС.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Основа | Форк **baresip-studio**, ветка `video` (приложение baresip+) | Готовое Kotlin/Compose-приложение: несколько учёток, TLS/WSS, SRTP/ZRTP, переводы, конференции, MWI, видео, ConnectionService. Linphone и PJSIP — GPL или платная лицензия и больше работы |
| Видео | Да (baresip+) | Вызывные панели, домофоны, видеозвонки между сотрудниками |
| Лицензия | **GPL, код открыт** (публичный TheRainOfSoul/HHPhone) | Нативные библиотеки видеоветки содержат x264/x265, bcg729, zrtpcpp (GPL). Бренд HH лицензией не затрагивается; Google Play принимает GPL-приложения |
| Настройка сотрудника | QR из приложения админа и (позже) из панели HHPBX, один формат | Работает с любой АТС, HHPBX — удобный бонус |
| Блокировка | Задаётся самим QR (`lock` + `pin`) | Админ/HHPBX полностью управляют тем, что видит сотрудник, без настройки на месте |
| Языки | ru, hy, en; по системе, иначе русский | Правило для всех приложений HH |
| Входящие в фоне | Постоянная регистрация через foreground-сервис baresip | Работает с любой АТС. Push (FCM) — позже, только для HHPBX |

## 1. Основа, репозиторий, сборка

- Репозиторий `G:\HHPhone`, GitHub **TheRainOfSoul/HHPhone** (публичный). Ветка `main` растёт от `upstream/video` (`https://github.com/juha-h/baresip-studio`). Обновления: `git fetch upstream && git merge upstream/video`.
- Kotlin-пакет `com.tutpro.baresip.plus` **не переименовывается** (на нём JNI-имена нативной библиотеки и каждое слияние с upstream). Меняется только `applicationId` → `am.dgsolutions.hhphone`, ставится рядом с baresip+.
- Наш код — в новых файлах `HH*.kt`; в файлах upstream только точечные правки (тема, строки, точки входа QR/блокировки), чтобы слияния были дешёвыми.
- Нативные библиотеки — по `juha-h/libbaresip-android` (ветка `video`, Makefile, NDK той же версии, что `ndkVersion` в `app/build.gradle.kts`), сборка на ВМ **hhpbx-build** (192.168.109.131, Debian). Результат (`.a` + заголовки в каталоге distribution, который ждёт `app`) кладётся в репозиторий; пересборка только при обновлении baresip.
- Подпись выпусков: `%USERPROFILE%\.hhphone\android-release.jks` + `keystore.properties` (вне git, терять нельзя). Выпуск: тег `vX.Y.Z`, APK в GitHub Releases.
- Не трогаем сейчас: SMS/MMS, блокировку номеров, чат — остаются как у upstream.

## 2. Оформление HHDesign

- Меняются `Theme.kt` и `Colors.kt` (Material 3 color scheme), экраны не перекрашиваются поштучно.
- Светлая тема: бордо `#7A0C2A` — цвет действия (главные кнопки, активная вкладка, ссылки), поверхности и текст графитовые. Тёмная: заливки `#9E1B3A`, ссылки/акценты `#E0607A`. Ошибки — отдельный красный.
- Кнопки «Позвонить» зелёная и «Сбросить» красная — как во всех звонилках, не бордо.
- Шрифт Noto Sans (системный на Android, не вшивается).
- Иконка: в `G:\HHDesign/brand/products.json` новый продукт `phone` («HH Phone», глиф Fluent `phone`), иконки через `scripts/icons.mjs`; адаптивная иконка Android вручную: `android-foreground.png` + фон `#7A0C2A`. Иконка уведомлений монохромная.
- «О программе»: HHPhone, версия, ссылка на исходники, благодарность и лицензии baresip / TutPro Inc. (BSD-3) и компонентов (GPL).

## 3. Языки

- `values/` — английский (база upstream, правим упоминания бренда).
- `values-ru/` — upstream-перевод + недостающие строки + строки HH.
- `values-hy/` — новый перевод всех строк (делает Claude, вычитывает пользователь — особенно телефонные термины).
- Остальные `values-xx/` upstream удаляются. `locales_config` — выбор языка в настройках Android 13+. Язык по умолчанию при прочих системных языках — русский (русские строки в `values/` невозможны без поломки слияний, поэтому: `values/` остаётся английским, а при старте, если системный язык не ru/hy/en, приложение при старте выставляет себе `ru` — способ (per-app locale API или переопределение Configuration) выбирается в плане 1 по тому, как upstream уже обрабатывает язык).
- После каждого слияния с upstream `lint` (MissingTranslation) показывает новые непереведённые строки.

## 4. QR-код

Содержимое — ссылка `hhphone://add?c=<base64url(JSON без паддинга)>`:

```json
{ "v": 1,
  "name": "Отель Орбели",
  "user": "201", "pass": "…", "domain": "pbx.orbeli.am",
  "authUser": "…",
  "proxy": "sip:pbx.orbeli.am:5061;transport=tls",
  "transport": "udp",
  "mediaEnc": "srtp",
  "lock": true, "pin": "4821" }
```

- Обязательные: `v`, `user`, `pass`, `domain`. Остальное необязательно; `transport` по умолчанию `udp`; `mediaEnc` ∈ `srtp`, `srtp-mand`, `dtls_srtp`, `zrtp` (значения baresip), по умолчанию нет. `pin` — 4–8 цифр, требуется при `lock: true`.
- `v` ≠ 1 → «QR от более новой версии, обновите HHPhone». Неизвестные поля игнорируются.
- Одна учётка на QR.
- JSON превращается в учётку через существующие `Account`/`Api` baresip (как ручное добавление). Если учётка с таким AoR уже есть — спросить «Заменить?».
- Сканирование: (1) системная камера — deep link `hhphone://add` открывает приложение; (2) кнопка «Добавить по QR» в списке учёток — сканер `com.journeyapps:zxing-android-embedded` (Apache 2.0, без Google-сервисов).
- Генерация (телефон админа): в карточке учётки «Показать QR» → переключатель «Блокировать у сотрудника» + поле PIN → QR через `zxing-core`. Подпись: «QR содержит пароль — не публикуйте».
- Позже (план 3) панель HHPBX выдаёт QR того же формата.

## 5. Блокировка (режим сотрудника)

- Режим — на весь телефон. Включается QR с `lock: true`; хранится флаг + PIN как PBKDF2-хэш с солью (SharedPreferences приложения).
- В режиме сотрудника **можно**: звонить, история, контакты, чат, голосовая почта, громкость. **Нельзя** (пункты скрыты): добавить/изменить/удалить учётку, видеть пароль, настройки приложения (кодеки, сеть, звук), «Показать QR».
- Новый QR на заблокированном телефоне: PIN в QR совпадает с текущим → учётка добавляется сразу; иначе приложение спрашивает текущий PIN (при успехе блокировка и PIN берутся из нового QR).
- Пункт меню «Админ» → PIN → полный доступ до ухода приложения в фон; там же «Снять блокировку».
- 5 неверных PIN подряд → пауза 5 минут (время ошибки хранится, перезапуск не сбрасывает).
- Забыли PIN → очистка данных приложения в настройках Android и повторное сканирование. Это ожидаемо и описано в памятке.

## 6. Тестирование

Автотесты (JVM) — только наш код:
- QR: разбор и сборка туда-обратно, `v` ≠ 1, битый base64/JSON, нет обязательных полей, `lock` без `pin`, лишние поля;
- PIN: хэш/проверка, пауза после 5 ошибок, переживает перезапуск;
- правила добавления по QR при блокировке: тот же / другой / отсутствующий PIN.

Живая проверка (эмулятор + ВМ hhpbx-test 192.168.109.132, номера 100/101, второй участник — pyVoIP):
1. учётка по QR: регистрация, исходящий и входящий звонок, входящий при свёрнутом приложении;
2. видео: звонок на эхо-тест FreeSWITCH, виртуальная камера эмулятора;
3. блокировка: запрещённое скрыто, «Админ» с PIN открывает;
4. языки ru/hy/en — нет английских остатков в ru/hy;
5. не-HHPBX АТС: ручная учётка (TLS, нестандартный порт).

На реальном телефоне (энергосбережение Xiaomi/Huawei, Bluetooth, камера) — финальная проверка пользователем по памятке `docs/testing.md`.
