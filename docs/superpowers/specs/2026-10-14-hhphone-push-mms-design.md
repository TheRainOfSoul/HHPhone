# HHPhone 0.8.0 — без постоянного уведомления (push), MMS из системы, отчёты о доставке, удаление и объединение контактов, мелочи

Дата: 2026-10-14. Основа: HHPhone 0.7.0 (спека 2026-10-14-hhphone-contacts-design.md).

## Цель

Закрыть всё отложенное: значок уведомления как у других SIP-звонилок, полная SMS/MMS-переписка, отчёты о доставке,
удаление и объединение контактов, мелочи 0.7.0.

## Как делают другие (поиск 2026-10-14)

- Acrobits/Groundwire: постоянная SIP-регистрация на Android ненадёжна (Doze, App Standby, батарея OEM); приложению
  «не нужно работать в фоне в простое» — станция → push-relay → FCM → приложение просыпается → REGISTER → звонок.
- Zoiper: бесплатная версия держит фоновое подключение (батарея, отключения), платная — push; Sipnetic, Linphone —
  push, а «фоновый режим» (постоянное подключение) — отдельная настройка для серверов без push.
- Вывод: **push по умолчанию, постоянное подключение — только где push нет или по желанию.** У HHPBX push уже есть
  (HHPhone 0.4.0, проверено: пробуждение ~1,5 с, после смахивания из недавних, в энергосбережении).

## Дизайн

### 1. Режим push без постоянной службы (пункт 10)

- **Когда:** у всех учёток станций push принят станцией (`HHPush.isPush(aor)`), настройка «Постоянное подключение»
  выключена (по умолчанию). SIM-звонки и SMS не зависят от службы (InCallService, SmsReceiver).
- **Что:** служба останавливается сама («Stop» — снятие регистрации, остановка), когда HHPhone не на экране и нет
  звонка, через 30 с покоя (после ухода с экрана, после конца звонка, после старта от push/SMS). Уведомления
  статуса нет — значка нет.
- **Звонок:** станция видит, что регистрации нет → push → HHPhone стартует, регистрируется, звонок приходит (как сейчас
  после смахивания из недавних).
- **Открыл приложение** — служба стартует как обычно (регистрация, статус на время работы).
- **Нет push у какой-либо учётки** (другой сервер, не HHPBX) или настройка включена — как сейчас: постоянная служба
  с тихим уведомлением.
- Меню ⋮: «Постоянное подключение» (галочка) — prefs `hh_ui/keep_alive`.
- Сообщения через станцию — push и хранение недоставленных (п. 6); индикатор голосовой почты обновляется при запуске.

### 2. MMS из системы и групповые беседы (пункт 7)

- `HHSms.threads/thread` читают и `content://mms` (входящие/исходящие): текст (`part` `text/plain`) и картинки
  (`part` `image/*` → `content://mms/part/<id>`), адреса из `content://mms/<id>/addr` (137 — от кого, 151 — кому).
- Беседа — по `THREAD_ID` системы. Групповая беседа (несколько адресов) — одна строка «Имя1, Имя2…», в чате у
  входящих подпись отправителя. Ответ в групповую беседу — вне объёма (кнопка отправки скрыта, подсказка).
- `Message.images` для системных MMS — `content://` URI (ChatScreen показывает через Coil `AsyncImage` — работает).
- MMS, полученные HHPhone до 0.8.0 (файлы в `mms_images`), показываются как сейчас.

### 3. Отчёты о доставке SMS (пункт 8)

- `HHSms.send`: `deliveryIntents` на каждую часть → `HHSmsSentReceiver` (действие «delivered») пишет
  `Sms.STATUS` (`COMPLETE`/`FAILED`) в строку базы.
- Чат: у исходящих SIM-сообщений — «✓» отправлено, «✓✓» доставлено, «!» ошибка (из `TYPE`/`STATUS` системы).

### 4. Удаление и объединение контактов (пункт 9)

- Карточка, меню ⋮ в шапке: «Удалить контакт» (подтверждение) → `delete(Contacts/<id>)` (все сырые контакты,
  синхронизация разнесёт); baresip-контакт — `Contact.removeBaresipContact`.
- «Объединить с…» → список контактов (поиск) → `AggregationExceptions TYPE_KEEP_TOGETHER` между основным сырым
  контактом этого и каждым сырым контактом выбранного; карточка перезагружается на объединённый контакт.
- «Разделить» — вне объёма.

### 5. Мелочи 0.7.0 (пункты 1–6)

1. «Создать контакт» из `sip:user@чужой-домен` — в карточку полный адрес (тип SIP), не `user`.
2. Строки правки номеров — стабильный `key` (новым строкам — отрицательный временный id; `numberOps` считает
   `id ≤ 0` новыми); правка переживает поворот (`rememberSaveable`).
3. Запасное удаление из `CallHistoryNew` — по времени **и** номеру, одной записью файла.
4. Кеш имён `HHPeople` — ключ для `sip:` с чужим доменом — полный адрес (а не `peerKey`), перезвон — по полному URI.
5. Группировка журнала — подряд идущие звонки одного номера (как в Google «Телефон» и Samsung): **без изменений**,
   полная история номера — «История звонков». (Ruling: пункт 5 списка — ожидаемое поведение.)
6. Новое сообщение, пока HHPhone открыт, **не** открывает беседу само — только уведомление и жирная строка в «Чатах».

### 6. Push и хранение для сообщений станции (HHPBX 1.12.0 + HHPhone)

Решение пользователя: push для сообщений **с хранением недоставленных**.

- **HHPBX, chatplan** (`chatplan/default.xml`, контекст `default`): `lua app/hhphone_push/message.lua`.
  - получатель — номер этого домена и зарегистрирован → обычная доставка (скрипт ничего не делает);
  - не зарегистрирован, у номера есть токены HHPhone (`v_hhphone_push`) → push `{"t":"msg"}` (тот же ключ FCM, что
    для звонков), ожидание новой регистрации до 10 с (как `index.lua`), затем доставка `chat` API;
  - не проснулся или нет HHPhone → сообщение в таблицу `v_hhphone_messages` (домен, кому, от кого, текст, время);
  - хранится 7 дней; не больше 200 на номер (старые вытесняются).
- **Доставка сохранённых:** обработчик события `sofia::register` (`lua.conf.xml` hook) →
  `app/hhphone_push/deliver.lua` — по порядку времени `chat` API получателю, удаление доставленных.
- **Схема:** таблица создаётся миграцией HHPBX (как `v_hhphone_push`), ru/hy/en не нужны (нет интерфейса).
- **HHPhone:** push `t=msg` → запустить службу (как для звонка) и перерегистрироваться; уход в сон через 30 с покоя
  (п. 1). Сообщение показывается обычным уведомлением.
- **Проверка (стенд HHPBX):** номер без регистрации + токен → push уходит (поддельный ключ, как в
  `hhphone-push-scenarios.sh`), сообщение сохраняется; регистрация `sipreg.py` → сообщение доставлено и удалено;
  номер без HHPhone → сохраняется и доставляется при регистрации; 201-е вытесняет 1-е.

### 7. Меню контакта и мессенджеры (HHPhone)

- Нажатие на контакт в «Контактах»/«Избранном» открывает то же меню, что в журнале (нижняя панель): шапка;
  для каждого номера — строка с кнопками вызова по линиям и SMS; «История звонков» (по всем номерам контакта),
  «Карточка контакта», «Скопировать номер» (первый; у строки номера — свой значок копирования). «Удалить из
  журнала» — только в меню из журнала.
- В меню (из журнала и из контактов) — «WhatsApp», «Viber», «Telegram», если приложение установлено:
  - номер в международном виде (`+`; номер с 0 — через страну SIM `PhoneNumberUtils.formatNumberToE164`);
  - WhatsApp: `https://wa.me/<цифры>`; Viber: `viber://chat?number=%2B<цифры>`; Telegram: `tg://resolve?phone=<цифры>`;
  - видимость пакетов: `<queries>` в манифесте (`com.whatsapp`, `com.whatsapp.w4b`, `com.viber.voip`,
    `org.telegram.messenger`, `org.telegram.messenger.web`).
- Строки ru/hy/en.

## Чистая логика (JUnit)

- `HHUiLogic.pushOnly(stations: List<Boolean>, keepAlive: Boolean): Boolean`.
- `HHUiLogic.numberOps` — `id ≤ 0` = новый.
- `HHUiLogic.mmsAddresses(rows)` — отправитель/получатели по типам 137/151, без своего номера.
- `HHUiLogic.deliveryMark(type, status)` — «✓», «✓✓», «!».
- `HHUiLogic.messengerLinks(e164)` — ссылки WhatsApp/Viber/Telegram; `HHUiLogic.toE164(number, countryCode)`.
