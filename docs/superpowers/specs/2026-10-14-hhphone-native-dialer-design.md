# HHPhone 0.6.0 — как обычная звонилка: системный журнал, системные SMS, роли

Дата: 2026-10-14. Основа: HHPhone 0.5.1 (новый интерфейс, спека 2026-10-13-hhphone-ui-design.md).

## Цель

HHPhone ведёт себя как обычное приложение «Телефон» и «Сообщения» Android: показывает всю историю звонков и всю
переписку SMS телефона (в том числе сделанную до установки HHPhone), ничего не прячет у себя и ничего не теряет
при переустановке, смене SMS-приложения или удалении HHPhone.

## Решения пользователя

- Единый журнал звонков — системный `CallLog`. Звонки через станцию тоже пишутся туда.
- Единая база SMS — системный `Telephony` провайдер. Вкладка «Чаты» показывает всю SMS-переписку телефона
  плюс сообщения через станцию.
- MMS-картинки в этой версии: как сейчас (входящие MMS с картинками остаются в сообщениях HHPhone),
  полноценное чтение системных MMS — позже.
- При первом запуске HHPhone один раз предлагает стать звонилкой и SMS-приложением по умолчанию.

## Как сейчас (найдено в коде)

- `BaresipService.deleteSystemCallLog` после каждого SIM-звонка удаляет его из системного журнала, копия живёт
  только в `CallHistoryNew` (файл `call_history`). Снятие роли/SIM удаляет аккаунт `sip:mobile@pstn` вместе
  с его журналом и SMS (`BaresipService.kt` uaEvent create → `CallHistoryNew.clear`, `Message.clearMessagesOfAor`).
- В манифесте есть `WRITE_CALL_LOG`, нет `READ_CALL_LOG`; разрешения выдаются вместе с ролью звонилки.
- Входящие SMS (`SmsReceiver` → `handleIncomingMessage`) и исходящие (`ChatScreen` → `Utils.sendSms`,
  `sendTextMessage` без деления длинных текстов) в системную базу не пишутся — хотя это обязанность SMS-приложения
  по умолчанию.
- Роли запрашиваются только переключателями в Настройках.

## Дизайн

### 1. Журнал звонков (`HHCallLog.kt`, новый)

- **Больше не удаляем** системные записи: вызов `deleteSystemCallLog` убирается вместе с функцией.
- **Звонки через станцию пишутся в `CallLog`** в двух местах, где сейчас создаётся `CallHistoryNew` для SIP
  (звонок закрыт; входящий отклонён автоматически), если у аккаунта включён журнал:
  - `NUMBER` — номер собеседника (`HHUiLogic.peerKey`), `DATE` — начало (или время конца, если не отвечен),
    `DURATION` — секунды разговора;
  - `TYPE`: исходящий → OUTGOING; входящий отвеченный → INCOMING; отклонён (`rejected`) → REJECTED;
    не отвечен → MISSED;
  - `PHONE_ACCOUNT_ID` = aor станции (`sip:101@домен`) — по нему журнал узнаёт звонок станции,
    `PHONE_ACCOUNT_COMPONENT_NAME` — компонент `ConnectionService` HHPhone;
  - `NEW` = 1 для пропущенных (системный счётчик пропущенных).
  - Без разрешения `WRITE_CALL_LOG` запись молча пропускается.
- **Вкладка «Телефон» читает `CallLog`**, если есть `READ_CALL_LOG` (добавить в манифест):
  - строка с `PHONE_ACCOUNT_ID`, начинающимся с `sip:` и равным aor одной из учёток HHPhone (или любым `sip:`) —
    звонок станции: `peer = sip:<NUMBER>@<домен aor>`, `aor` = `PHONE_ACCOUNT_ID`;
  - остальные строки — SIM: `peer = tel:<NUMBER>`, `aor = sip:mobile@pstn` (пометка «SIM», перезвон с SIM);
  - TYPE → `HHLogEntry`: INCOMING/OUTGOING — `start` задан; MISSED — `start = null, rejected = false`;
    REJECTED/BLOCKED — `start = null, rejected = true`; VOICEMAIL — как MISSED;
  - скрытый номер (`NUMBER` пустой или `PRESENTATION` ≠ ALLOWED) — `tel:anonymous`, без перезвона;
  - последние 500 записей, сортировка по `DATE` по убыванию.
- **Обновление на лету**: `ContentObserver` на `CallLog.Calls.CONTENT_URI` → `HHHistory.bump()`.
- **Без `READ_CALL_LOG`** (HHPhone не звонилка по умолчанию) журнал работает по-старому из `CallHistoryNew`.
- `CallHistoryNew` продолжает вестись (старые экраны baresip, записи разговоров) — источник для вкладки
  меняется, данные baresip не трогаем.
- **Перенос один раз** (флаг `hh_ui/calllog_migrated`, после получения `WRITE_CALL_LOG`): все записи
  `CallHistoryNew`, которых нет в `CallLog` (совпадение номер + время ±5 с), вставляются в `CallLog` —
  это SIM-звонки, удалённые прежними версиями, и звонки станции.

### 2. SMS (`HHSms.kt`, новый)

- **Входящие SMS** записываются в `Telephony.Sms.Inbox` прямо в `SmsReceiver.onReceive` (до старта сервиса —
  чтобы не потерять при сбое), если HHPhone — SMS-приложение по умолчанию: `ADDRESS`, `BODY`, `DATE`
  (время получения), `DATE_SENT` (из PDU), `READ = 0`, `SEEN = 0`, `SUBSCRIPTION_ID`.
- **Исходящие SMS** (`Utils.sendSms`): длинный текст — `divideMessage` + `sendMultipartTextMessage`;
  перед отправкой запись в `Sms.Outbox`, по результату (`PendingIntent` отправки) — тип SENT или FAILED и статус
  сообщения в чате (`MESSAGE_UP` / `MESSAGE_UP_FAIL`) с сохранением (сейчас статус не сохраняется).
- **Вкладка «Чаты»**, если есть `READ_SMS`:
  - SMS-беседы берутся из системы: последнее сообщение каждого `THREAD_ID` (адрес, текст, время, непрочитанные);
    строка открывает чат `aor = sip:mobile@pstn`, `peer = tel:<адрес>`;
  - к ним добавляются беседы HHPhone не по SIM (сообщения через станцию) и SIM-беседы HHPhone с картинками MMS,
    если такой беседы нет в системе; общая сортировка по времени;
  - имя и фото — из контактов, как сейчас.
- **Экран чата для SIM** (`ChatScreen`, aor `sip:mobile@pstn`): сообщения беседы читаются из системы по
  `THREAD_ID` (`Telephony.Threads.getOrCreateThreadId(адрес)` — объединяет +374… и 0…), плюс сообщения HHPhone
  с картинками; при открытии чата SMS беседы помечаются прочитанными (`READ = 1`, `SEEN = 1`);
  удаление сообщения удаляет его и из системы.
- **SIM-сообщения больше не хранятся в `messages` HHPhone** (кроме MMS с картинками) — источник правды система.
  Уведомление о входящем SMS и счётчик непрочитанных остаются как сейчас.
- **Перенос один раз** (флаг `hh_ui/sms_migrated`, после получения роли SMS): SIM-сообщения из `messages`
  HHPhone, которых нет в системе (адрес + текст + время ±5 с), вставляются в системную базу.
- **Без роли SMS / без `READ_SMS`** — чаты работают по-старому из `messages`.

### 3. Роли по умолчанию (`MainActivity`)

- При запуске, если роль звонилки не у HHPhone и ещё не спрашивали (`hh_ui/dialer_asked`), — системный запрос
  `ROLE_DIALER`; затем так же один раз `ROLE_SMS` (`hh_ui/sms_asked`). Не поверх звонка, не одновременно
  с другими запросами (после окна полноэкранных уведомлений).
- После выдачи роли — то, что делает переключатель в Настройках: запрос `READ_PHONE_STATE`/`READ_PHONE_NUMBERS`,
  команда сервису «Check Roles» (`addMobileUserAgent`), перенос журнала/SMS.
- Отказ уважаем: больше сами не спрашиваем, переключатели в Настройках остаются.

## Чистая логика (JUnit, `HHUiLogic`)

- `callLogEntry(number, type, date, duration, accountId, presentation): HHLogEntry` — отображение строки CallLog.
- `callLogType(dir, start, rejected): Int` — тип для записи звонка станции.
- `sameCall(...)` / `sameSms(...)` — совпадение для переноса (номер/адрес + время ±5 с, текст).

## Проверка

- JUnit на всю чистую логику.
- Эмулятор `HHPhone_Test` (звонилка и SMS по умолчанию):
  - `adb emu gsm call` — входящий SIM-звонок → строка в журнале HHPhone и в системном журнале (`content query`);
  - звонок станции (100 ↔ 101) → строка в системном журнале с `PHONE_ACCOUNT_ID = sip:101@…`, в журнале
    HHPhone — с пометкой станции, перезвон идёт через станцию;
  - `adb emu sms send` — SMS видна в `content://sms/inbox` и во вкладке «Чаты»; ответ уходит, лежит в `sent`;
  - длинное SMS (> 160 знаков) уходит частями;
  - SMS, вставленная в систему до HHPhone (`content insert`), видна в «Чатах»;
  - переустановка поверх — журнал и SMS на месте;
  - без ролей — журнал и чаты по-старому.
- Выпуск 0.6.0 (versionCode 11).

## Вне объёма

- Чтение системных MMS (картинки из чужих приложений), групповые MMS.
- Отчёты о доставке SMS.
- Запись разговоров в системный журнал (остаётся в старом экране baresip).
